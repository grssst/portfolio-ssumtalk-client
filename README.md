# 썸톡 (SumTalk)

> **동네에서 새로운 사람을 만나고 대화할 수 있는 소셜 앱**
>
> 실제 서비스를 직접 기획하고 개발하여 Google Play 및 앱스토어에 출시·운영한 프로젝트입니다.

---

## 📱 프로젝트 소개

**썸톡(SumTalk)** 주변의 새로운 사람을 발견하고 채팅할 수 있도록 만든 소셜 모바일 애플리케이션입니다.

단순한 토이 프로젝트가 아니라 실제 사용자를 대상으로 서비스를 출시하고 운영하면서,
클라이언트 개발뿐만 아니라 **백엔드 API 연동, 인증, 결제, 이미지 처리, 실시간 채팅, 서비스 운영 과정**까지 경험하기 위해 제작했습니다.

프로젝트의 전체 개발 과정에서 프론트엔드 개발을 직접 담당했으며, 백엔드 및 AWS 인프라까지 직접 구축하여 실제 서비스 형태로 운영했습니다.

---

## 🎯 프로젝트 목표

* 실제 사용자가 사용할 수 있는 모바일 서비스 개발
* Android / iOS를 하나의 코드베이스로 개발
* 사용자 인증부터 채팅, 결제까지 서비스에 필요한 핵심 기능 구현
* 실제 배포 및 운영을 통한 서비스 개발 경험
* 사용자 피드백과 운영 데이터를 기반으로 서비스 개선

## 🛠️ 기술 스택

### Client

| 기술                      | 사용 목적                   |
| ----------------------- | ----------------------- |
| React Native            | 모바일 애플리케이션 개발           |
| Expo                    | React Native 개발 및 빌드 환경 |
| Expo Router             | 파일 기반 화면 및 네비게이션 구성     |

| AsyncStorage            | 로컬 데이터 저장               |

### Backend / Infrastructure

| 기술              | 사용 목적           |
| --------------- | --------------- |
| Java            | 백엔드 개발          |
| Spring Boot     | REST API 서버     |
| Spring Security | 인증 및 보안         |
| JPA / Hibernate | 데이터베이스 연동       |
| MySQL           | 관계형 데이터베이스      |

| AWS RDS         | MySQL 데이터베이스 운영 |
| AWS S3          | 이미지 및 파일 저장     |
| AWS CloudFront  | 이미지 CDN         |
| AWS DynamoDB    | 채팅 데이터 저장       |
| AWS Lambda      | 서버리스 기능         |
| AWS SQS         | 비동기 작업 처리       |

## ✨ 주요 기능

### 👤 회원가입 및 로그인

* 회원가입 / 로그인
* 사용자 인증
* 로그인 상태 유지
* 사용자 프로필 관리

### 🧑‍🤝‍🧑 사용자 탐색

* 다른 사용자 프로필 확인
* 프로필 이미지 확인
* 사용자 정보 기반 탐색
* 관심 사용자와 상호작용

### 💬 1:1 채팅

* 사용자 간 채팅
* 채팅방 관리
* 메시지 송수신
* 채팅 데이터 저장

채팅 데이터는 일반적인 관계형 데이터와 분리하여 **Amazon DynamoDB**를 활용했습니다.

### 🖼️ 이미지 업로드

사용자가 프로필 및 서비스 내 이미지를 업로드할 수 있도록 구현했습니다.

이미지는 서버에 직접 저장하지 않고 **Amazon S3**에 저장하고,
**CloudFront CDN**을 통해 클라이언트에서 빠르게 불러올 수 있도록 구성했습니다.

### 🍬 유료 재화 시스템

서비스 내에서 사용할 수 있는 재화를 구현했습니다.

* 재화 구매
* 서비스 기능 이용 시 재화 차감
* 구독 상품
* 무료 이용 기간 관리

결제 및 구매 상태에 따라 클라이언트 UI가 동적으로 변경되도록 구현했습니다.

## 🔄 API 통신 구조

클라이언트와 서버는 REST API를 기반으로 통신합니다.

```text
┌─────────────────────┐
│   React Native App  │
│                     │
│  UI / State / API   │
└──────────┬──────────┘
           │ HTTPS
           ▼
┌─────────────────────┐
│    Spring Boot      │
│       API Server    │
└──────────┬──────────┘
           │
     ┌─────┼─────┐

   MySQL   S3  DynamoDB
```

이미지와 채팅 데이터처럼 데이터 특성에 따라 저장소를 분리하여 구성했습니다.

## 📊 실제 서비스 운영

썸톡은 개발 완료 후 실제 앱 마켓에 배포하여 운영했습니다.

단순히 기능 구현에 그치지 않고 실제 사용자가 서비스를 이용하는 환경에서 다음과 같은 경험을 쌓았습니다.

* 모바일 앱 출시
* 서버 및 데이터베이스 운영
* AWS 인프라 관리
* 사용자 문의 및 오류 대응
* 서비스 데이터 및 사용 패턴 확인
* 앱 업데이트 및 유지보수
* 운영 비용 관리
* 결제 시스템 운영

이를 통해 개발 단계에서는 경험하기 어려운 **서비스 운영 단계의 문제와 의사결정**을 직접 경험했습니다.

## 💡 개발하면서 경험한 것

### 1. 클라이언트와 서버를 함께 고려한 개발

단순히 화면을 구현하는 것이 아니라,

```text
사용자 행동
   ↓
React Native UI
   ↓
API 요청
   ↓
Spring Boot
   ↓
Database / AWS
   ↓
API Response
   ↓
Client State 업데이트
   ↓
UI 반영
```

전체 데이터 흐름을 고려하여 기능을 구현했습니다.

### 2. 실제 서비스에서 발생하는 예외 처리

실제 사용자를 대상으로 운영하면서 정상적인 상황뿐만 아니라 다양한 예외 상황을 처리해야 했습니다.

* 네트워크 오류
* API 요청 실패
* 인증 만료
* 이미지 업로드 실패
* 서버 오류
* 데이터가 존재하지 않는 경우
* 중복 요청
* 결제 및 재화 처리 예외

이를 통해 단순한 기능 구현보다 **사용자가 오류를 만나도 서비스를 계속 사용할 수 있도록 만드는 것**이 중요하다는 것을 경험했습니다.

### 3. 서비스 운영 비용에 대한 경험

개발 과정에서는 기능 구현에 집중하기 쉽지만 실제 서비스에서는 서버, 데이터베이스, 스토리지, CDN 등의 비용도 중요한 요소였습니다.

실제 서비스를 운영하면서 **기술 선택이 곧 운영 비용과 연결된다는 점**을 경험했고, 사용량에 맞는 인프라 규모와 비용을 고려하게 되었습니다.
